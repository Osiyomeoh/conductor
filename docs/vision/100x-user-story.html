Conductor · the production user story

Conductor at 100x

The best agent makes the human manage less, while increasing the truth of what actually got done.

A north-star reference: a day in the life of the fully realized product. This is the target, not the current build. The honest "where we are today" delta is at the end, so it doubles as a roadmap.

Invariant 1

Done is a claim, not a fact.

No language model has a path to "done." Only a real check, run in real isolation, can complete work.

Invariant 2

Attention is the budget.

Agent labour is cheap and parallel; the reviewer is neither. Nothing is dispatched that cannot be reviewed.

The story

Once
· setup ·

Act 0 — Setup

Alex signs in with SSO; Conductor never handles a password, only a signed token carrying the org and role. Alex connects the real tools: GitHub (work in branches, open draft PRs, never force-push), CI (a commitment's proof can be the real pipeline job), Slack (a bot for human tasks, not agent noise), and read-only cloud signals so "touches production" is detectable.

Then Alex builds the team: people are invited and join with their own SSO; agents are hired, not configured, each arriving on probation and earning a lighter check as it proves out. Setup is done. From here, Alex mostly talks and mostly waits.

Mon 9:00

Act 1 — A sprint from a conversation

Walking to the office, Alex opens Conductor on mobile and speaks:

"Onboarding redesign by Friday, Sarah owns design. The payment webhook is dropping retries, fix it and prove it with a test. Competitive research on three onboarding tools. Rewrite the empty-state copy. Agents can take the webhook, the research, and the copy."

Within seconds, a plan: human and agent commitments separated, every one carrying the check that will prove it, written before any work starts. Two vague asks ("improve onboarding", "tidy the code") are refused with a reason: no evidence requirement. Alex edits one line by voice and says "approve." The loop starts.

Mon
· running ·

Act 2 — The work dispatches itself

No forms, no manual assignment, no status meetings. Sarah gets a Slack message with her definition of done. Agent commitments go into isolated git worktrees; each writes real code, none can mark its own work done. The attention ledger holds surplus verified work rather than dumping twelve unreviewable PRs on Friday. The board updates itself.

Mon 11:40

Act 3 — An agent lies, and is caught

The webhook agent finishes early and reports done, confidently. The diff looks clean. Conductor does not believe it, and runs the declared evidence, the real regression test in CI:

  1. The check fails (the retry backoff is off by one). The claim is rejected, and never reaches Ravi's queue.
  2. The worktree is destroyed. The wrong code never touched the base branch.
  3. The agent's trust for backend work drops immediately.
  4. Recovery re-dispatches with the failure as context; the retry passes CI, and only then does a draft PR open with verified work.

Ravi reviews correct code, once. He never saw the wrong version. The whole episode is three events and twelve cents of compute.

Tue 14:10

Act 4 — The quiet protection of attention

Ravi goes silent on a blocking commitment. Conductor runs graduated recovery on its own, soft then firmer, without escalating. The decision surface stays empty all morning. Then exactly one item appears, ranked by what it unblocks:

Decide the onboarding paywall position. Unblocks 4 commitments and frees ~90m of review. Two viable options, and what each already costs.

It arrives in Slack. Alex reads it for twenty seconds and answers once. Everything else was already handled.

overnight

Act 5 — The night it worked while Alex slept

That decision had been open since Monday. Rather than wait, Conductor had already forked the plan across every plausible answer, built each branch in isolation, verified them, and discarded the losers. Cost: a few cents. Attention spent before the moment of choice: zero. When Alex picks an answer, the follow-on work is already built and verified, and merges immediately.

Fri 8:30

Act 6 — The quiet morning

The decision surface reads "Nothing needs you." The board is accurate and nobody updated a status all week. The trust ledger reflects real performance. Cost per verified commitment came in under budget. The event log can answer any "why is this done?" Alex's attention was spent on two decisions, all week. The redesign shipped, the webhook is fixed and proven, the research is on the desk. The best day was the quiet one.

The production capabilities behind the story

Identity & access

SSO/OIDC, org and workspace scoping, role-based access, every action attributable to a person or a named agent acting for one.

Real integrations

GitHub/GitLab (branches, draft PRs, branch protection), CI as evidence, Slack/email/mobile delivery, two-way issue-tracker sync.

The team as a model

Invite humans; hire agents from a roster, and at the edge a marketplace rated by verified track record. Probation and earned trust per kind of work.

Verification substrate

Isolated git worktrees, real checks (tests, commands, schema, HTTP, human review). Pass merges, fail is destroyed. Never decorative.

Attention & policy

A per-person attention budget that gates dispatch, and a policy engine routing AUTO / APPROVE / BLOCK with hard blocks that never proceed.

Speculation

While a decision waits, build every plausible answer in isolation, verify, and discard the losers, so the chosen path is already real. Cost-bounded.

Durability & scale

Event-sourced state on DynamoDB, partitioned per tenant, replayable and resumable, multi-instance and highly available, multi-org.

Cost governance

Per-role model pricing, a live cost ledger, per-verified-commitment accounting, hard budget ceilings with alarms. Spend is a visible number.

Observability

The control loop as traces, dashboards for throughput, catch rate, held work and attention, and alarms on what matters.

Security

Secrets in a manager, least-privilege task roles, sandboxed agent actions, and an audit trail that is the event log itself.

Failure modes it handles by design

  • A confidently wrong agentCaught by verification before any human sees it; trust drops; recovery re-dispatches.
  • A human goes silentGraduated recovery and reassignment, without escalating until a real decision is required.
  • A decision blocks progressSpeculation builds the answers ahead of time; the human answers once and it is already done.
  • Too much verified workHeld with a reason, not dumped on a queue nobody can clear.
  • A risky actionDeploy, refund, customer email: blocked by policy, escalated to an approver, never auto-executed.
  • A cost spikeBudget ceilings and alarms; speculation is bounded; the loop degrades to held, not runaway spend.
  • A restart or lost instanceState resumes from the durable log; no work or trust is lost.

Reality delta — today vs the 100x target

Real today · verified, deployed
  • Voice dictation into a live LLM planner that attaches a proof to every commitment and refuses the unprovable.
  • The catch, on real git worktrees with real checks, on AWS App Runner and Bedrock AgentCore Runtime.
  • Decisions ranked by attention freed, speculative branches, the attention budget, trust ledger, cost, event log.
  • Local real-repo execution (gated): isolated worktrees, merge only on a passing check, never pushes.
  • Per-visitor isolation, rate limits, input caps, event-sourced DynamoDB persistence for real tenants.
The 100x gap · not built yet
  • SSO/OIDC login and RBAC (the boundary exists; JWKS validation is a stub).
  • GitHub/GitLab integration: OAuth, clone, draft PRs. Today it is a local path only, no push.
  • Slack / email / mobile delivery of tasks and decisions. No Slack code exists yet.
  • Building a team from the UI: the roster is seeded; onboarding's "invite" is cosmetic.
  • Two-way voice conversation. Today voice is one-way dictation.
  • CI-as-evidence, tracker sync, agent marketplace, multi-instance HA, tracing dashboards, budget alarms.

The through-line: the hard, differentiating core is real — verification, attention, speculation, policy, trust, on real git and real AWS. The 100x gap is the collaboration and integration surface around that core: identity, the git host, the delivery channels, and a team you build rather than one that ships seeded.
